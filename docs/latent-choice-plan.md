# 本周计划：城市 latent + agent latent 网络，基线上的消融检验（2026-10-28）

分支 `research/latent-choice`。只用已有的基线运行做离线训练，不跑 MATSim。

## 问题

第 k 轮有人试了一个新方案。用第 k 轮之前就有的信息，预测**新方案执行后的得分是否高于被复制的旧方案**。

- 这是提议器需要的能力：把有希望的方案挑出来。
- 参照（H1，`archive/h1-proposal-predictor.md`）：只用旧方案得分，改时间 AUC 约 0.70，找路约 0.73；换方式用"同区域同换法的人"约 0.86。

## 网络

```
城市编码器    2 km 格子 × 小时的道路拥堵（通行时间 / 自由流、进入数）→ 图网络 → e[格子, 小时]
agent 编码器  活动链（类型、格子、结束时间）+ 方案记忆摘要 → 小 Transformer → z
方案编码器    每段出行：方式、出发小时、e[起点, 小时]、e[终点, 小时] → 小 Transformer → h
打分头        MLP([z, h_新, h_旧, z⊙h_新, z⊙h_旧, 旧方案得分]) → 新方案更好的概率
```

参数量不超过 100 万。城市特征这周只有道路，没有公交拥挤。

## 检验

| 版本 | 改动 |
|---|---|
| 完整网络 | — |
| 去掉城市 latent | e 换成不随城市变化的常数 |
| 去掉 agent latent | z 只用人群和出行数 |
| 参照 | 只用旧方案得分 |

- 数据：种子 4711 抽 5 万人训练，同一批人在种子 4712 上测试；第 10–70 轮，每 10 轮一个快照。
- 指标：AUC，按试新方案的类型（换方式、改时间、找路）分开报告。
- 每个版本训练 2 次，差别小于两次之间的差就不算差别。

## 判断（先写下）

- **继续**：完整网络在三类上都比参照高 ≥ 0.03，且去掉城市或 agent 至少一项下降 ≥ 0.02。
- **删掉**：某一项去掉后下降 < 0.01。
- **停下来想**：完整网络不比参照高 0.03。

## 步骤

1. 建环境：`~/matsim-work/venv-latent`，装 PyTorch。
2. 解析快照：每人每个方案的出行序列和得分（2 个种子 × 7 个快照，CPU 作业）。
3. 城市张量：路段逐小时记录 → 格子 × 小时。
4. 拼样本：新方案、旧方案、人、城市状态、标签。
5. 训练：3 个版本 × 2 次（GPU）。
6. 把结果写进下面的"结果"一节。

- 驱动 590.48，CUDA 13.1：PyTorch 自带 CUDA 的版本可以直接用，不需要加载 CUDA 模块。
- 每次训练预计在 6 小时以内，所以用 `mit_normal_gpu` 就行，不用处理抢占。同时最多 2 个作业。
- 数据准备（第 2–4 步）只用 CPU，放在 `mit_preemptable` 上。

## 结果（10-28，作业 27091530）

**数据：** 每个种子 49,676 人（crc32 抽样）；175,924 个样本（训练 79,086、验证 9,038、测试 87,800），三类试新方案各约 5.9 万。"新方案更好"的比例：换方式 27%，改时间 48%，找路 48%。城市张量 557 个格子 × 30 小时。网络 76 万参数，每个 epoch 几秒（L40S）。

**测试 AUC（种子 4712，两次训练的均值 [范围]）：**

| 版本 | 全部 | 换方式 | 改时间 | 找路 |
|---|---|---|---|---|
| 参照：只用旧方案得分 | 0.560 | 0.643 | 0.520 | 0.542 |
| 完整网络 | **0.737** [0.735–0.738] | **0.931** [0.930–0.932] | 0.566 [0.555–0.577] | 0.596 [0.587–0.605] |
| 去掉城市 latent | 0.725 [0.724–0.725] | 0.921 [0.920–0.923] | 0.548 [0.547–0.549] | 0.597 [0.596–0.597] |
| 去掉 agent latent | 0.736 [0.734–0.737] | 0.928 [0.927–0.928] | 0.580 [0.578–0.582] | 0.588 [0.584–0.591] |

收费区相关人群：完整网络换方式 0.902、改时间 0.540、找路 0.633（不相关人群 0.941、0.576、0.581）。

**按事先写下的标准：**

- **比参照高 ≥ 0.03：满足。** 换方式 +0.29，改时间 +0.05，找路 +0.05。
- **去掉城市或 agent 至少一项下降 ≥ 0.02：不满足。** 去掉城市：换方式 −0.010、改时间 −0.018、找路 +0.001（前两项超出两次训练的范围，是真实差别，但不到 0.02）。去掉 agent：换方式 −0.003、找路 −0.008，改时间反而 +0.014。
- **删掉规则：** agent latent 在三类上都没有下降 ≥ 0.01，按规则下一版删掉。城市 latent 在换方式、改时间上下降 ≥ 0.01，保留。
- 所以**不进入 MATSim 探针**，先改网络。

**怎么理解：**

1. **信号几乎全在换方式上，而且来自方案本身。** 三个版本换方式都在 0.92–0.93，远高于参照的 0.64，也高于 H1 的分组预测器（0.86，标签口径不同，不能直接比）。三个版本都保留了方案编码器（方式、出发时段、起讫格子、活动类型），所以"这种换法在这个地方好不好"主要是方案编码器学到的。
2. **城市 latent 有用，但量不大。** 去掉它，换方式和改时间各下降 1–2 个点，找路不变。城市特征只有道路拥堵，没有公交拥挤，而换方式的好坏很大程度取决于公交。
3. **agent 消融不干净。** 方案 token 里已经有起讫格子和活动类型，agent 编码器的信息大部分已经在方案里了，所以去掉它几乎没影响。这说明"agent latent 没用"的结论要打折扣：真正独立的 agent 信息（时间约束、历史成败）这一版没有给进去。
4. **改时间、找路的标签噪声很大。** 新方案更好的比例约 48%，大量新方案和旧方案几乎一样（重新找路找回同一条路），所以 AUC 天花板很低。
5. 参照 AUC 比 H1 低（0.52–0.64 对 0.70–0.73），因为这里的标签是"比父方案好"，H1 是"比自己记忆里最好的方案好"。

**下一版的改动（建议）：**

- 城市特征加公交：每个格子每小时的等车时间和上不去车的次数（可以从 `research/persons-*` 按活动地点汇总，或从事件里算）；
- agent 编码器改为只放方案里没有的信息：试过哪些方式、各自的得分、活动的最早和最晚时间；去掉和方案重复的格子、活动类型；
- 改时间、找路的标签改为"明显更好 / 明显更差"（|差| > 1），去掉近似相等的样本，再看城市 latent 对它们有没有用；
- 代码：`experiments/latent/`（`extract_plans.py`、`city_tensor.py`、`build_samples.py`、`train.py`）；数据和结果在 ORCD `/orcd/pool/007/weibingw/matsim-data/latent/`（`results.json`）。

## 第二版（10-28，跑之前写下）

同样的问题、同样的三个版本和参照、同样的判断标准。改三处：

| 改动 | 第一版 | 第二版 |
|---|---|---|
| 城市特征 | 只有道路（第 k−1 轮） | 道路 + 公交：每个格子每小时的公交出行数、平均等车分钟、等车超过 20 分钟（或没上车）的比例（第 k−10 轮，只有每 10 轮才有上车时间；`transit_tensor.py`） |
| agent 编码器 | 活动链（类型、格子、结束时间）+ 摘要 | 只放方案里没有的：记忆里每个方案一个 token（方式比例、相对父方案的得分、存在多少轮、由哪种策略生成、出发时间相对父方案平均挪了多少） |
| 标签 | 全部样本 | 改时间、找路只保留 \|新 − 旧\| > 1 的样本（训练和测试都去掉近似打平的）；换方式不变 |

去掉近似打平后，改时间保留约 51%，找路保留约 26%（看了第一版样本的分布）；这两类里"新方案更好"的比例约 47%。去掉城市 latent 时，道路和公交一起换成常数。

## 第二版结果（10-28，作业 27123191）

**数据：** 去掉近似打平后训练 46,696、验证 5,367、测试 52,076（换方式 29,306、改时间 15,140、找路 7,630）。"新方案更好"的比例：换方式 27%，改时间 47%，找路 47%。公交特征：等车超过 20 分钟的比例从第 0 轮的 16% 降到第 60 轮的 7%，两个种子一致。

**测试 AUC（种子 4712，两次训练的均值 [范围]）：**

| 版本 | 全部 | 换方式 | 改时间 | 找路 |
|---|---|---|---|---|
| 参照：只用旧方案得分 | 0.624 | 0.643 | 0.527 | 0.634 |
| 完整网络 | **0.866** [0.865–0.867] | **0.943** [0.942–0.943] | **0.678** [0.675–0.681] | **0.787** [0.779–0.795] |
| 去掉城市 latent | 0.843 [0.841–0.844] | 0.929 [0.929–0.929] | 0.630 [0.630–0.630] | 0.780 [0.772–0.787] |
| 去掉 agent latent | 0.839 [0.839–0.840] | 0.931 [0.930–0.931] | 0.628 [0.626–0.631] | 0.714 [0.705–0.723] |

收费区相关人群：完整网络换方式 0.916、改时间 0.662、找路 0.802（不相关人群 0.952、0.687、0.768）。

**按事先写下的标准：**

- **比参照高 ≥ 0.03：满足。** 换方式 +0.30，改时间 +0.15，找路 +0.15。
- **去掉城市或 agent 至少一项下降 ≥ 0.02：满足，而且两项都满足。** 去掉城市：改时间 −0.048、换方式 −0.014，找路 −0.007（在两次训练的范围内，不算差别）。去掉 agent：找路 −0.073、改时间 −0.050、换方式 −0.012。
- **删掉规则：** 两项都有下降 ≥ 0.01 的类型，都保留。
- 所以**按规则进入下一步：MATSim 探针。** 探针要改 MATSim 的重规划，属于"跑 MATSim"，先和用户确认再做。

**怎么理解：**

1. **agent latent 这次有用了，主要在找路。** 记忆里的方案（试过什么、得分多少、由哪种策略生成）对"重新找路会不会更好"帮助最大（+0.07）。第一版的 agent 信息和方案重复，所以看不出作用。
2. **城市 latent 主要帮改时间。** 去掉后改时间降 0.05，比第一版（0.018）大得多。改时间好不好取决于那个时段的拥堵，现在多了公交等车，信号更完整。不过这一版同时改了三处，没有单独拆出公交特征的贡献。
3. **改时间、找路的提升有一部分来自去掉近似打平的样本**，测试集变了，和第一版的数字不能直接比。和各自的参照比：改时间从 +0.05 到 +0.15，找路从 +0.05 到 +0.15。
4. 公交状态滞后 10 轮（只有每 10 轮有上车时间）。第 20 轮以后城市变化慢，影响应该不大，但前几个快照会更粗。

**还没做的：**

- 单独拆出"加公交"和"去掉打平"各自的贡献（同一套代码，各跑一个变体即可，GPU 几分钟）；
- MATSim 探针：用网络对创新方案排序，看能否用更少的迭代达到同样的政策效应（需要用户同意）。
