# 基线预训练 + 政策适配器（2026-10-28，跑之前写下）

分支 `research/latent-choice`。只用已有运行，不跑新的 MATSim。

## 0. 想法

- **第一阶段（只用基线）：** 网络只学两样东西：城市（路网和公交本身的结构）和人（这个人本身：人群、一天的活动安排）。不碰任何政策。
- **第二阶段（上政策）：** 冻结第一阶段的编码器，只训练一个很小的适配器，把政策（收费）接进去。
- **检验：** 如果只训练一个小适配器，网络就能在新政策下工作，说明它学到的城市和人是可迁移的；如果必须整个网络重新训练，说明它只是记住了基线。

这一步检验的是"表示能不能迁移"，还不是直接预测政策效应，也还没有放进 MATSim。最终打分仍由 MATSim 做（总纲不变）。

## 1. 现在的网络为什么还不行，要改什么

| 部分 | 第三版的输入 | 问题 | 第四版改成 |
|---|---|---|---|
| 城市 latent | 某次运行观测到的道路拥堵（第 k−1 轮）、公交等车（第 k−10 轮）；外加每个格子的身份嵌入 | 学的是一次运行的**状态**，不是路网**本身**；格子身份嵌入只能记住"这个格子"，换路网就没用 | **结构**：每个格子的道路长度、车道公里、通行能力、平均限速、高速路段比例、坐标；每个格子每小时的公交到站班次（地铁、公交分开）。**状态**（拥堵、等车）作为单独一支，可以开关 |
| agent latent | 记忆里存着的方案和得分 | 是这个人在某次运行里的**经历**，换政策后就变了 | **人本身**：人群类型 + 初始方案（`cold.xml.gz`）里的活动链：每个活动的类型、所在格子、开始结束时间、时长。**经历**（记忆）作为单独一支，可以开关 |
| 方案 token | 方式、时间、起讫格子、活动、计划行程时间等 | — | 不变；另加"这段出行穿过几条收费路段"（基线下价格为 0） |

数据里的人只有人群和车辆编号两项属性，没有年龄、收入。所以在这个模型里，"人本身"就是人群 + 一天的活动安排；它们在所有运行里相同，不随政策变。

## 2. 第一阶段：能不能这样训练出来（基线）

任务和第三版相同：第 k 轮的新方案执行后会不会比父方案好。数据相同（种子 4711 训练，4712 测试，去掉改时间、找路的近似打平）。各版本都用第三版的逐段对照、策略类型、辅助回归。

| 版本 | 城市 | agent | 回答什么问题 |
|---|---|---|---|
| 第三版（参照） | 状态 + 格子身份 | 经历 | — |
| **结构 + 本身** | 只有结构，不用格子身份 | 只有人本身 | 只靠路网和人，能做到多少 |
| 结构 + 本身 + 状态 + 经历 | 结构 + 状态 | 本身 + 经历 | 状态和经历还能加多少 |
| 结构 + 本身，去掉城市 | 常数 | 人本身 | 结构有没有用 |
| 结构 + 本身，去掉 agent | 结构 | 只有人群 | 人本身有没有用 |

**判断（先写下）：**

- **可以这样训练：** "结构 + 本身"比第三版低不超过 0.03（全部 AUC），且去掉城市、去掉 agent 各自至少在一类上下降 ≥ 0.02。
- **结构学不到东西：** 去掉城市下降 < 0.01。那就说明城市的信息主要在状态里，结构只是摆设，要重新想城市 latent 怎么学（例如加辅助任务：从结构和需求预测拥堵）。
- 第二阶段用"结构 + 本身"这一版（不带状态和经历），因为状态和经历本身就随政策变。

## 3. 第二阶段：政策适配器

收费在 MATSim 里只改两件事：开车穿过收费路段要付钱；大家改变选择后拥堵变了。所以适配器接在两处，都初始化为"什么也不改"：

- **方案 token：** 每段出行要付的钱（穿过的收费路段数 × 当时的价格）和它乘以这个人的金钱边际效用，经一个小线性层加到 token 上；
- **城市 latent：** 每个格子每小时的收费强度（收费路段数 × 价格），经一个小网络给城市向量乘一个系数、加一个偏移。

适配器的参数控制在网络的 5% 以内。

**数据：** 政策运行没有重规划日志，用方案快照找出新方案和父方案，执行得分取 `research/persons-k`（在基线上核对过：和重规划日志的执行得分完全一致，差 < 0.00003）。Schema 1、Schema 2 各取种子 4711、4712 的第 10–70 轮。

| 版本 | 训练 | 回答什么问题 |
|---|---|---|
| 不改 | 不训练，基线网络直接用 | 不告诉网络有收费，会差多少 |
| **适配器** | 冻结编码器，只训练适配器（Schema 1，种子 4711） | 表示能不能迁移（主要结果） |
| 适配器、10% 数据 | 同上，只用 10% 的样本 | 需要多少政策数据 |
| 全部微调 | 整个网络在 Schema 1 上继续训练 | 适配器损失了多少 |
| 从头训练 | 只用 Schema 1 的数据训练一个新网络 | 基线预训练有没有帮助 |

测试：Schema 2 的种子 4712（换了价格、也换了种子），同时报告 Schema 1 的种子 4712（只换种子），把"换价格"和"换种子"分开。重点看收费区相关人群。

**判断（先写下）：**

- **成立：** 在 Schema 2 上，适配器比"不改"高，离"全部微调"不到 0.01，并且比"从头训练"高 ≥ 0.02；
- **预训练没帮助：** 从头训练和适配器差不多；
- **表示不可迁移：** 适配器明显低于全部微调（> 0.02）。

## 4. 对照：直接预测 vs 在网络里迭代（已在跑，作为基准）

同时在跑一个不用神经网络的对比：从基线运行的结果直接预测收费效应（九项政策效应里的三项主要指标）。方法有：不变、按价格线性放大、logit 选择（只算收费 / 加拥堵反馈迭代）、梯度提升树直接预测、两者混合。用 Schema 1 训练、Schema 2 测试，再反过来。代码 `experiments/latent/policy_predict.py`。

它的结果是以后"适配器 + 政策效应输出头"要打败的基准。已知一个：按价格线性放大从 Schema 1 推 Schema 2，得到 −13,294，真值 −11,053，误差是 ε 的 3 倍。

两个收费方案是同一批 289 条收费路段，只有高峰价格不同（$9.18 / $14）。所以这里能检验的只是"换价格"，检验不了"换收费区"。

## 5. 步骤

1. 结构输入：每个格子的道路结构，每个格子每小时的公交班次（`city_static.py`）；每个人的初始活动链（`cold.xml.gz`）。
2. 重新解析方案，加上每段出行穿过的收费路段数：基线 2 个种子、两个收费方案各 2 个种子，第 10–70 轮。
3. 拼样本：基线（同第三版）和政策运行（快照 + `persons-k`）。
4. 第一阶段训练和消融（GPU）。
5. 第二阶段适配器（GPU）。
6. 结果写在下面。

## 5a. 检查后的修订（10-28，任何结果出来之前）

重新检查了方案、训练、结构和流程，改了下面几处：

1. **政策运行的标签核对过：** 在基线第 40 轮上，用快照找出的新方案（12,498 个）和重规划日志完全一致：同一批人、同样的策略类型、同样的父方案；执行得分和日志相差 < 0.00003。所以政策运行的样本和基线是同一口径。
2. **"只做算术"的对照（toll_only）：** 执行得分里本来就含有"−金钱边际效用 × 收费"。适配器有可能只是学会了减去这笔钱，这不能说明表示可迁移。所以加一个对照：冻结网络，只学一个系数乘以"金钱边际效用 × （新方案收费 − 父方案收费）"，再加一个偏置。适配器必须比它好，才说明迁移的不只是算术。
3. **没见过的人：** "人本身"（一天的活动安排）几乎是每个人独有的，网络可能只是记住了人。crc32 % 10 == 1 的那 10% 的人在两个阶段都不参与训练，所有结果另外报告他们的 AUC。
4. **从头训练也给 10% 数据（scratch_10）：** 只有这样，"适配器、10% 数据"对"从头训练、10% 数据"才能说明基线预训练的价值；全量数据时，政策样本和基线样本一样多，从头训练自然也不差。
5. **一个错误已修正：** 适配器的方案输入里有"穿过几条收费路段"，基线下这个数也不为零，训练后的适配器会改变基线的结果。现在只在真正收费的场景里输入它，适配器在基线上恒等于零（在基线测试集上可以核对：'none' 和 'adapter' 应该完全相同）。
6. **检验不到的东西（写明）：** 两个方案的路网和收费区都一样，所以"结构"相对"格子身份表"的优势（换一个路网、关一条路也能用）在这里检验不出来，只能看两者在基线上是否一样好、对没见过的人是否一样好。以后可以用"留出一片区域"来检验。

**补充的判断（先写下）：**

- 第一阶段：结构 + 本身在没见过的人上，比见过的人低不超过 0.02（全部 AUC）；否则说明它在记人。
- 第二阶段：适配器在 Schema 2 上比 toll_only 高 ≥ 0.01（全部 AUC），才算迁移了算术以外的东西；适配器 10% 比从头训练 10% 高 ≥ 0.02，才算基线预训练有帮助。

## 6. 结果

### 6.1 基准：直接预测 vs 在网络里迭代（作业 27131648，`results-policy/`）

表中是 |预测 − 真值| / ε，3 个种子的均值，越小越好；< 1 表示在 ε 以内。"真值"是同一批抽样的人（12.8%）在政策运行第 90 轮和最终方案里的结果。

| 方法 | 方案 1 → 方案 2（外推到更高价格）：相关人群小汽车段数 / 小汽车比例 / 公交比例 | 方案 2 → 方案 1（内插到更低价格） |
|---|---|---|
| 不变 | 13.9 / 5.5 / 0.6 | 11.7 / 3.9 / 1.6 |
| 按价格线性放大 | 3.3 / 0.4 / 1.8 | 2.3 / 0.3 / 1.2 |
| 迭代：只算收费，最终方案池 | 3.5 / 0.4 / 3.0 | 3.2 / 0.1 / 1.1 |
| **迭代：只算收费，方案池并集** | **0.03** / 1.1 / 4.0 | **1.1** / 1.0 / 1.8 |
| 迭代：并集 + 拥堵反馈 | 0.2 / 1.0 / 3.9 | 1.2 / 0.9 / 1.8 |
| 直接预测（梯度提升树） | 3.9 / 1.7 / 1.3 | 1.1 / 1.5 / 1.5 |
| 混合 | 3.8 / 1.3 / 2.2 | 0.2 / 0.8 / 1.8 |

迭代方法的 logit 尺度在训练政策上标定，两个方向都选出 β = 0.5（MATSim 是 1）。

**按事先写下的标准：** 没有一种方法在两个方向上三个主要指标都落在 ε 以内，"可用"不成立。

**怎么理解：**

1. **主要指标（收费区相关人群小汽车段数）上，迭代 + 方案池并集最好**（两个方向平均 0.55ε），直接预测最差（2.5ε），比按价格线性放大（2.8ε）好不了多少。
2. **决定成败的是方案池，不是迭代本身。** 同样的计算，只用基线最终方案池时误差 3.3ε，用第 40–90 轮快照的并集时降到约 0.5ε。和热启动失败的原因一致：最终方案池里缺少收费下才会选的方案。
3. **拥堵反馈几乎没有作用**（0.03 → 0.2，1.1 → 1.2）。个别格子的拥堵比变化可达 1.2，但对相关人群开车段数的影响很小。在这两个价格之间，均衡反馈不是主要矛盾。
4. **直接预测只能内插，不能外推：** 从高价格学、预测低价格时误差 1.1ε，反过来是 3.9ε。它在一个价格上学到的反应，换到更高的价格时不会自己变强。混合版在内插时最好（0.2ε），外推时仍然失败。
5. **公交比例的误差都大，但这一项的"真值"本身不可靠：** 抽样真值是 +0.00029，原流程是 +0.00084，相差的比 ε 还大。小汽车段数的抽样真值也有偏差（方案 2：−10,263 对原流程 −11,053，差 1.1ε；三个种子 −9,352 到 −11,469，波动比原流程大三倍）。所以这个基准大约只能分辨 1ε 以上的差别，0.03ε 有运气成分。要更准，需要用全部人和第 90–99 轮的平均作真值。

**对网络设计的启发：** 能外推的是"用 MATSim 的打分算收费 + 足够丰富的方案池"这一结构，纯数据驱动的直接预测外推不了。这支持"适配器"的做法：收费通过明确的输入（每段出行的钱）进入网络，而不是让网络从一个价格的数据里猜反应曲线。
