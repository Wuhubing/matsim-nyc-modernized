# [44] Zhang, Ao, Yan, Jin, Li 2024 — A GPU-accelerated large-scale simulator for transportation system optimization benchmarking

- **Venue**: arXiv 2406.10661（v1 2024-06-15；v2 2024-10-02）。清华大学 FIB 实验室，模拟器名为 MOSS，代码 github.com/tsinghua-fib-lab/moss-benchmark（MIT 许可）
- **Domain / Tier / Priority**: GPU & parallel simulation / 3 / Medium（候选轻量模拟器，支持拥堵收费，含 NYC）
- **Link**: https://arxiv.org/abs/2406.10661v1
- **依据**: ✅ 已读 v1 全文和 **v2 全文**（arXiv PDF，含附录 A–H）。v2 比 v1 多了真实感验证、实现细节（附录 B）和完整数值表。下面的数字以 v2 为准。标【推断】的是我们的映射。

> 一句话（摘要）：基于学习的交通系统优化需要与真实感强的微观模拟器大量交互，但现有微观模拟器在大规模场景下效率很低，而且主要只支持信号控制。本文提出**第一个开源的 GPU 加速大规模微观交通模拟器**：在 **2,464,950 辆车**的大场景中以 **84.09 Hz** 迭代，比最好的基线（CityFlow）快 **88.92 倍**。提供 Python API 和可控对象，在 4 个城市上对 5 类优化场景（规则方法、RL、黑箱优化）做 benchmark。

## 1. 瓶颈
RL 和黑箱优化需要大量环境交互，城市级（≥10 万辆车）场景要求模拟频率至少约 10 Hz；现有 CPU 模拟器（即使是 64 线程的 CityFlow 等）模拟一小时仍要数分钟（§1–2）。

## 2. 手段
- 车辆级微观模型：IDM 跟驰（δ = 4）+ **随机化 MOBIL** 换道（礼让系数 0.1，换道概率 2×10⁻⁸ 到 0.9，用来打破对称）；红黄灯前按 IDM 减速停车。
- **不建模路口内的冲突和优先权**：作者说在大规模仿真中建模它会导致死锁（与 CBLab 相同的处理），因此路口真实感依赖于无冲突的信号相位设置——作者自己列为局限。
- CUDA 实现：**两阶段并行（读写分离）**，用快照保存上一步的公共属性，避免读写冲突；用双向有序链表维护车道内的车辆索引，每个节点再加 4 个指向左右车道前后车的"侧指针"，查询邻车只需一次指针操作（避免线程分支）；prepare/update 两阶段各用 3–4 个 CUDA 异步流。所有仿真都在 GPU 上，只有写文件在 CPU 上（计时不含写文件）。
- 输入：地图 + 出行需求。需求包括车辆的起点、终点、出发时间和**已选路径**。工具链可以从卫星影像等公开数据生成地图和真实感 OD 矩阵。
- 5 个优化场景：信号控制、动态车道分配、潮汐车道、**拥堵收费**、道路规划；4 个城市：北京、上海、巴黎、纽约。

## 3. 省在哪一项
**每步计算**。

## 4. 快了多少，代价是什么
- 最大数据集（Roadnet-L：93,564 条路、26,479 个路口、2,464,950 辆车，3600 步）：**42.81 s vs CityFlow 3806.7 s**，即 88.92 倍（正文一处写 88.09，按两数相除应为 88.92）。硬件：64 线程 Xeon 8462Y + RTX 4090。10 Hz 下可模拟的规模：SUMO < 1 万辆、CityFlow 约 13 万、CBLab 约 15 万、本文 > 1000 万。
- **真实感（v2 新增）**：深圳 156,856 个摄像头记录的出行作为输入、422 万条 GPS 轨迹作为真值，比较 1,341 条路 8–9 点的平均速度：本文 RMSE = 8.5 km/h、相关系数 0.77；CityFlow RMSE = 16 km/h、0.53。
- 拥堵收费 benchmark 中，"each driver has three candidate routes"，每 20 秒调一次价格。正常拥堵下 Δ-toll 最好（如纽约 ATT 4,549 s vs 不收费 4,682 s，通过量 78,182 vs 72,765）；RL 方法 EBGtoll 反而比不收费更差。
- benchmark 数据是合成的：OSM 地图 + 扩散模型生成的 OD，**全部假设开车**，只保留早晚高峰，路径用 A* 按最短时间预先算好；按到达率 95%/90%/80% 定义畅通/正常/拥堵（纽约正常级为 262,706 个出行）。
- 代价：**没有活动链、没有 mode/出发时间选择、没有 MATSim 式的共同演化 replanning**。路径作为需求输入给定，收费场景中只在 3 条候选路径之间选择。

## 5. 怎么证明结果没变
主要比较速度；v2 加了深圳的路段平均速度对比（见第 4 问）。benchmark 比较的是优化算法，而不是模拟准确性；benchmark 结果没有误差棒（v1 的 NeurIPS 检查表自己承认没有报告误差棒，也没有写局限）。

## 6. 假设
车辆级微观模型；需求（含路径）外生给定；没有行为均衡。

## 7. 能否用于 MATSim？怎么用
**🟡 不能直接代替 MATSim；可以作为轻量实验平台或 LF 模型：**
- 【推断】若需要一个快速试验"均衡加速"思路的平台，需要自己在外面包一层 replanning 循环（路由 + 选择 + 得分），工作量不小。
- 【推断】作为多保真度中的 LF 交通模型（给创新打分）理论上可行，但微观 IDM 模型与 QSim 的排队模型差别大，LF 与 HF 的相关性需要先验证（[34](34_Peherstorfer2018_multifidelity_survey.md)）。
- 【推断】本文把 MATSim 描述为"匀速运动 + 路口排队、不考虑加减速"的中观模型，认为不适合 AI 优化——从另一个角度说明 MOSS 和 MATSim 处在不同的精度/速度位置，两者的结果不能直接互换。
- 支持拥堵收费，并有 NYC 场景，与我们未来的政策场景相关。
- 次问题参考：GPU 微观仿真约两个数量级加速，与 [42 GEMSim](42_Saprykin2019_GEMSim.md)、[43 LPSim](43_Jiang2024_LPSim.md) 一致。
