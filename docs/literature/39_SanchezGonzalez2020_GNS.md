# [39] Sanchez-Gonzalez et al. 2020 — Learning to simulate complex physics with graph networks

- **Venue**: ICML 2020（arXiv 2002.09405v2）
- **Domain / Tier / Priority**: Learned simulators / 3 / Low
- **Link**: https://arxiv.org/abs/2002.09405v2
- **依据**: ✅ 已读全文（arXiv v2：§1–6 和附录 A–D，含 **附录 C.6 推理时间表**、C.7 失败案例、D 与 CConv/DPI 的比较）。标【推断】的是我们的映射。
- ⚠️ 旧版笔记说可以"在 GPU 上快速推理"，对应到 RQ1 是**误导性的**。原文附录 C.6 明确说 GNS 的推理时间**与原仿真器相当**，而且本文的目标**不是**加速。

> 一句话（摘要）：GNS（Graph Network-based Simulators）把物理系统表示为粒子图，用学习到的消息传递计算动力学，能模拟流体、刚体、可变形材料及其相互作用。训练时只做单步预测（数千粒子），测试时能泛化到不同初始条件、**数千步**的 rollout、以及至少**多一个数量级**的粒子数。长期表现的主要决定因素是消息传递步数，以及**给训练数据加噪声**来缓解误差累积。

## 1. 瓶颈
传统仿真器（SPH、MPM 等）需要大量工程实现，且计算代价高（§1）。

## 2. 手段
- Encoder–Processor（M 步消息传递）–Decoder，预测加速度，再积分更新位置。
- **训练噪声**：给输入速度加随机游走噪声（σ = 3×10⁻⁴），使模型对自身 rollout 中的误差累积更稳健；rollout 精度在**中等**噪声尺度时最好；四种噪声方式中随机游走最好。作者认为这比"训练时用模型自己的多步预测"更便宜、泛化更好。
- 只用**单步损失**训练。附录 A 解释：用整条轨迹的损失训练，容量有限的模型可能学到"在某些步故意出错以换取长期表现"的偏差（例如把初始位置偷偷编码在小数位里），泛化反而变差。
- 训练：每个数据集约 1000 条训练轨迹、每条 300–2000 步；最多 2000 万次梯度更新；小数据集几小时，大数据集**最长约一周**（TPU/V100）。

## 3. 省在哪一项
原文的主要贡献是**精度和泛化**，不是计算量。

## 4. 快了多少，代价是什么（附录 C.6 原文数据）
- GNS（单块 V100 GPU，含邻域计算）vs 生成数据的仿真器（6 核 CPU）：GNS 每步时间是仿真器的 **51%–345%**。例如 WATER-3D（SPH）为 345%，SAND-3D（MPM）为 152%，WATER DROP（2D）为 51.3%。
- 第二张表：去掉邻域计算后，GNN 推理本身只占 GNS 每步时间的约 14%–90%，即**大部分时间花在邻域图的构建上**（在 CPU 上用 k-d 树算）。
- 原文："The learned GNS model has inference times comparable to that of the ground truth simulator … the main goal of this work was not to improve simulation time"。作者预期用更长的时间步或优化的邻域计算可以更快。
- 代价：需要大量仿真器生成的训练数据；分布外泛化有限；不保证物理守恒。

## 5. 怎么证明结果没变
rollout 的位置 MSE、最优传输距离、MMD 等分布指标；泛化测试（更多粒子、更长时间、未见过的形状）。
- 泛化：在 WATER RAMPS（2.5k 粒子）上训练，测试时面积大 32 倍、粒子数达 85k（34 倍）、rollout 5000 步（8 倍）仍视觉合理；CONTINUOUS 中训练时留出的摩擦角区间 [30°, 55°] 也能预测。
- 失败案例（C.7）：剧烈摇晃 1500 步后刚体方块开始变形；某个坏种子把 goop 预测为粘在墙上。

## 6. 假设
局部相互作用（图邻域）；有大量训练轨迹；训练和测试的动力学相同。

## 7. 能否用于 MATSim？怎么用
**🟡（远期）可以作为学习得到的 LF 模型，但不建议作为 RQ1 主攻方向：**
- 【推断】设想：在路网图上训练 GNN，输入各 link 的时变需求（由方案集推出），输出各 link 的时变出行时间，作为 mobsim 的便宜代理，给创新打分（多保真度过滤中的 LF，[34](34_Peherstorfer2018_multifidelity_survey.md)）。
- 理由不充分的地方：
  1. **本文没有证明学到的模拟器比原仿真器快**（附录 C.6），所以"用 GNN 代替 mobsim 来提速"没有文献支撑；
  2. 交通的溢出和排队是非局部、非线性的，GNN 精度存疑；
  3. 训练数据需要大量 MATSim 运行（每个场景都要）；
  4. PSim 已经提供了一个不用训练的 LF 模型，GNN 必须比 PSim 更好才有意义。
- 【推断】C.6 第二张表还说明：即使是学到的模拟器，瓶颈也可能在"数据结构/邻域计算"而不是模型本身——这与 MATSim 的情况相似（我们测到 mobsim 占 78% 且只用了 3.8/16 核），优化工程实现可能比换模型更直接。
- 可借的一点：**用加噪声训练来抵抗 rollout 误差累积**。若我们训练"创新有效性"模型，也应考虑训练与使用时的分布偏移问题。
