# [60] Yedavalli, Kumar & Waddell 2020 — Microsimulation Analysis for Network Traffic Assignment (MANTA) at Metropolitan-Scale for Agile Transportation Planning

- **Venue**: arXiv [2007.03614](https://arxiv.org/abs/2007.03614)；期刊版 *Transportmetrica A* 18(3):1278–1299, 2022（doi:10.1080/23249935.2021.1936281，据 [56] 的参考文献）
- **领域**: 12 GPU 与并行仿真（近期）
- **依据**: ✅ 已读全文（arXiv 2007.03614 **v2，2021-03**，12 页：§I–IX、表 I–II、参考文献）。

> 一句话：GPU 上的大规模交通微观仿真（IDM 跟驰 + 换道）。旧金山湾区九县早高峰约 320 万个 OD 对，0.5 s 步长的仿真约 **4.6 分钟**完成（不含路由和初始化）；作者线性外推 SUMO 微观仿真需要近 87 天（约 27,000×）。**但与 MATSim 的 JDEQSim（BEAM 中使用）相比只快 43%（6.6 vs 4.6 分钟）**。

## 1. 瓶颈
城市尺度的微观仿真要么只能做小区域，要么要靠昂贵的高性能计算，计算时间以天或周计。

## 2. 手段
- 路网来自 OSM（224,223 个节点、549,008 条边）；需求来自湾区 MTC 模型，5–12 点的小汽车出行 3,269,864 人次，起讫点在 TAZ 内均匀抽样；出发时间按 7:30 为中心、标准差 45 分钟的正态分布抽取。
- 路由：并行的优先队列 Dijkstra（MPI + OpenMP），**按距离**求最短路，320 万 OD 在一台 Intel i9 上约 62 分钟；32 个节点上强扩展到 1024 核接近线性。
- 仿真："traffic atlas"把每条路按 1 米切成格子，映射为连续内存，GPU 线程只查相邻格子；IDM 跟驰、强制/自由换道、间隙接受；交叉口只有两种简化：全红闪（逐车通过）或全绿。
- 校准：用 Uber Movement 路段速度，对 IDM 的 a、b、T、s₀ 做扰动范围逐轮缩小一个数量级的小批量搜索，5 轮收敛。

## 3. 省在哪一项
**每步计算**。

## 4. 快了多少，代价是什么（表 II）
| 仿真器 | 时间 (min) | 是否跑完 |
|---|---|---|
| MANTA (GPU) | 4.6 | 是 |
| **JDEQSim**（MATSim/BEAM，CPU 并行、事件驱动） | **6.6**（50 次平均） | 是 |
| SUMO 中观（简化 / 高级交叉口） | 1,620 / 1,740 | 是 |
| SUMO 微观（简化 / 高级交叉口） | 114,858 / 123,500 | **线性外推**（5000 个出行用了 194 分钟） |

- 代价与局限：
  - 路由（62 分钟）比仿真本身慢一个数量级以上；
  - 路径按距离一次给定，**没有迭代、没有均衡、没有拥堵反馈**；SUMO 慢的部分原因正是固定路径导致的局部严重拥堵；
  - 交叉口模型过于简化；需求是静态分配的五个时段，作者建议以后接 ActivitySim。

## 5. 怎么证明结果没变
- 路由：出行距离分布与加州家庭出行调查（CHTS）比较，均值 11.3 vs 13.5 km，中位数 6.46 vs 5.33 km；Bay Bridge 承担约 0.98% 的出行，与外部研究的 1% 一致。
- 仿真：与 Uber Movement 的 95,510 条路段（占 17%）速度分布比较；低速路段 MANTA 约慢 5 mph，高峰时段 MANTA 普遍偏慢，作者认为 IDM 对拥堵过于敏感。

## 6. 假设
路径给定后做一次仿真；没有行为反馈和均衡；所有车辆用同一组校准后的 IDM 参数（个体最高速度按路段限速加随机扰动）。

## 7. 对我们意味着什么
- 【推断】又一个"GPU 让 mobsim 快几个数量级，但其他环节（这里是路由）成为瓶颈"的例子，与 [42 GEMSim](42_Saprykin2019_GEMSim.md) 一致。
- 【推断】**新发现**：在同一个湾区场景上，MATSim 系的 JDEQSim（事件驱动、CPU 并行）只比 GPU 微观仿真慢 43%。所以"GPU 快几个数量级"主要是相对 SUMO 微观仿真，而不是相对 MATSim 已有的中观 mobsim；这削弱了"换 GPU mobsim 就能大幅加速 MATSim"的说法，进一步支持我们把重点放在减少迭代次数上。
- 只作为每步计算上限的参考。
