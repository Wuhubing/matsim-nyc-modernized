# 研究总纲：用已有信息减少 MATSim 的搜索和试错（2026-10-15 起）

**地位：** 本文优先于其他计划文档（`execution-plan.md`、`aggregate-regularity-plan.md`、`l2seg-replanning-plan.md`）。和它们冲突时，以本文为准。修改本文第 1–4 节需要用户同意。

**每个新会话：** 先读本文，再读 `HANDOFF.md`。动手之前，先说明这一步服务第 3 节的哪个假设。

---

## 1. 要解决的问题

**MATSim 的迭代是一个带噪声的、整个人群一起找不动点（均衡）的随机搜索：**
- 每轮随机挑 30% 的人做随机变异：时间变异、重新选路、换方式；
- 新方案只靠一次仿真打分；
- ExpBeta 在最多 5 个方案之间抽样。

`l2seg-replanning-plan.md` 第 8.2 节已经量化了这个搜索的三种浪费：
- **A. 重复提议：** 重新选路有 27–56% 得到和原来一样的路线；
- **B. 明显更差的提议：** 随机换方式，第一次评估的中位数比之前最好的低 8–10 分；
- **C. 在噪声之间选择：** 得分不做平均（`learningRate = 1`），步长不衰减。

**主要目的（10-15 用户确认）：** 为基于个体的交通仿真提供一套利用已有信息、更快到达质量可度量的均衡的方法，并给出何时可以停止的判据；在不改变政策结论的前提下，降低标定和政策分析中反复求均衡的计算量。

**为什么有意义：**
- MATSim 的迭代只是求稳态的计算手段，100 轮是惯例，不是标准（MATSim 书第 49 章）。
- 贵的是外层循环反复调用“跑到稳定”：标定（原论文 SPSA 每步 50 轮）、多政策 × 多种子的比较、政策设计（外层每试一个方案，内层求一次均衡）、敏感性分析。这些循环常常是串行的，不能靠并行解决。这和 L2Seg 加速被反复调用的内层求解器是同一处境。
- NYC 模型本身和实测相差很大（屏幕线 +75%），所以贡献是“更快求解这类仿真的均衡”的方法，NYC 是规模大、有公交和拥堵的测试场景，不是“更快得到正确的纽约交通状态”。

**目标：** 利用仿真过程中、以及之前运行中已经有的信息，减少到达均衡所需的搜索和试错，也就是减少轮数，或者减少每轮要处理的问题规模。

**这不是什么：**
- 不是工程优化。每轮成本的工程优化已经拿到 −26%，不再继续。
- 不是预测输出指标。用曲线或比例预测最终的方式占比（原 M1、M7），不产生仿真状态，只作为副产品。
- 不是修模型。模型按原样使用。

**和 L2Seg 的对应（忠实版）：**

| L2Seg | MATSim |
|---|---|
| 迭代求解器每一步只改动解的一小部分 | 每轮只有一部分人离自己的最优反应还远，其余的提议是重复或噪声 |
| 标签来自往前看一步的求解器（oracle） | 标签是每个人的**最优反应差距**（第 2 节），用当前路况在仿真前算出来，不是“下一轮会不会换计划”这种噪声标签 |
| 预测哪里会变，求解器只处理那里 | 只让差距大的人搜索，并且用已有信息提出有方向的提议 |
| 稳定段聚合成超节点，问题变小 | 差距接近零的人不再逐个仿真，变成背景负荷，每轮的问题变小 |
| 从求解器的运行记录里学 | 从之前的运行里学：热启动，以及学习谁会受政策影响 |

**以前对应得太浅的地方（不要重犯）：**
1. 把“聚合”理解成“冻结计划”：被冻结的人照样参与仿真，mobsim 占每轮 78%，所以省不了每轮成本。
2. 用“下一轮换不换计划”作为个人层面的标签：这个标签主要是 ExpBeta 的噪声，AUC 0.58–0.67 很可能是标签的问题，不能证明个人层面没有规律。
3. 把第 80 轮关掉创新后的状态当作靶子：它是人为截断的结果，不是均衡。

## 2. 主度量：均衡差距（gap）

**定义：**
- 对每个居民 i，在第 k 轮的环境下（第 k 轮的路段-小时通行时间、公交时刻和拥挤）：
  - gap_i = 最优反应的效用估计 − 执行方案的效用估计（≥ 0）；
  - 两边用同一个估计器，也就是同一套通行时间和打分公式。
- 总体：相对差距 G(k) = Σ gap_i / Σ |执行方案效用|。同时报告 gap_i 的分布（中位数、p90、gap ≈ 0 的人的比例）。

**分量，按顺序建：**
- **G_route：** 只换路线，方式和时间不变。`route_gap.py` 已有，用时间而不是广义成本，要补上距离成本。
- **G_mode：** 在可用方式里，用 router 估各方式的效用，取最好的。和 DiscreteModeChoice 的思路相同。
- **G_time：** 出发时间在 ±30 分钟的网格上取最好。最后做，可以先不做。

**估计器必须先验证（第 3 节的 H0）：** 估计的 gap_i 要能预测这个人真的换到更好方案后的实际得分提升。用 W1 日志里实际发生的换方案来检验。

**加速的定义（两条都要满足）：**
- 主指标：达到 G ≤ ε 所用的核时；ε 取原流程（RQ1 种子 4711）第 99 轮的 G。
- **政策结论不变：** 场景之间的差别（比如收费后开车占比、进入收费区次数、收费收入的变化）和完整流程一致，误差在种子噪声以内。需要一对场景：baseline 和一个政策场景（`actual2025`）。

**次要指标：**
- 和原流程最终状态的距离（方式占比、屏幕线，TV 和 σ）；
- 只报告，不作为通过标准。

这一节取代原来“严格标准（2σ）还是政策效应标准”的讨论。

**MATSim 自己的收敛定义（10-15 查证）：**
- MATSim 书第 49 章 49.1.1 节、第 4 章 4.5.3 节：要收敛到 logit 选择，需要**同时**关掉创新（方案集合固定）和打开得分的 MSA 平均（`fractionOfIterationsToStartScoreMSA`）。
- 迭代只是为了到达稳态分布，不代表真实的天数，也不是拟合。
- NYC 场景只关创新、不做平均（`learningRate = 1`），所以原流程第 80 轮以后的状态也不是书里定义的收敛。
- 含义：开了得分平均的 E1 更接近书的标准做法，H0 画收敛曲线时应作为参考之一。是否加内存重跑 E1 仍由用户决定（第 5 节暂缓清单）。

## 3. 核心假设（只有这四个）

每个假设都写明：要回答的问题、先做的深入分析、要做的实现、放弃标准。放弃标准在看到结果之前定好，看到结果之后不改。

### H0：gap 可以可靠测量，它刻画了原流程收敛慢在哪里（前提）

- **分析：**
  1. 建 G_route 和 G_mode 的估计器。
  2. 验证：估计 gap 和实际提升的 Spearman 相关；分开路线和方式。
  3. 用 RQ1 三个种子、E1、E2 每 10 轮的快照，画 G(k) 和 gap_i 的分布。
- **要得出的规律（不是一个数字）：**
  - G 在创新期是持续下降，还是很早就停在一个噪声底上？
  - 差距集中在哪类人身上（方式、子人群、OD），以及为什么？
  - 第 80 轮关创新时 G 跳了多少？这说明“漂移”到底是没找到好方案，还是找到了但选不中。
  - E1 和 E2 对 G 的影响，以及机制。
- **放弃或修正：** 如果估计 gap 和实际提升的相关 < 0.3，先修估计器（比如加入公交拥挤），H1–H3 都不开始。

### H1：有信息的提议能大幅减少到达 ε 的轮数（主线）

- **依据：** 8.2 节的 A 类和 B 类浪费；杠杆 2，按趋势提议的命中率是随机的约 4 倍；`StableReRoute` 能去掉 30% 白找的重新选路。
- **要实现的内容：**
  1. **挑人：** 创新名额按 gap_i 分配，而不是随机挑 30%；保留 ε 比例随机，用于探索。可以用已有的 W3 定向选择器，以 gap 作为优先级。
  2. **换方式：** 先用 router 估各方式的效用，按估计效用抽样，取代均匀随机。
  3. **重新选路：** 用 `StableReRoute` 跳过必然重复的那部分。
- **先做的分析：** 用已有快照离线回答：“如果第 k 轮按 gap 挑人、按估计效用提议，有多少提议会被接受？”和随机提议对比，并分开三种浪费各自贡献多少。
- **验证：**
  1. 12 轮检查流程和逐位一致（关掉新功能时）；
  2. 一次 100 轮（要用户同意）；
  3. 比较 G(k) 曲线，和达到 ε 的轮数。
- **放弃标准：** 达到 ε 的轮数比原流程少不到 30%，或者终点的 G 比原流程差。

### H2：差距接近零的人可以聚合成背景负荷，每轮的问题变小（L2Seg 的“聚合”）

- **先做的分析（不写 Java）：**
  - 每轮 gap_i ≈ 0 的人的比例，以及“下一段仍然 ≈ 0”的持续性，这是 L2Seg 意义上的“下一步稳定”；
  - 这些人占 mobsim 的多少：车辆·小时，公交载客。
  - 还要回答：他们的交通如果换成固定的路段-小时负荷，剩下的人感受到的环境会偏多少？用已有的路段-小时数据估计。
- **只有分析通过才实现：** 背景负荷注入 mobsim（要改代码，工作量大，实现前单独和用户确认方案）。
- **放弃标准：**
  - 第 40 轮时，gap ≈ 0 且持续的人的车辆·小时不到 30%；或者
  - 用背景负荷代替会让剩下的人的通行时间偏差超过种子噪声的 2 倍。

### H3：跨运行复用：新政策从已有的均衡热启动（“利用之前已有的信息”）

- **做法：**
  1. 新政策从 baseline 第 99 轮的计划（含全部方案和得分）出发；
  2. 在新政策的环境下算 gap_i，只让 gap 大的人重新搜索，可以和 H1 结合；
  3. 对应原计划的 RQ5、W5、W7。
- **需要：** 一次政策的冷启动参考运行（`actual2025`，100 轮，要用户同意），也就是原执行计划的 A-1。它同时也是 M7 副产品的数据。
- **验证：** 热启动达到同样 G 的核时，和冷启动比较。
- **放弃标准：** 节省的核时不到 50%，或者热启动的终点 G 比冷启动差。

**顺序：**
1. H0 先做，它是 H1–H3 的度量；
2. H0 通过以后，H1 是主线；
3. H2 先只做分析；
4. H3 的冷启动参考运行可以提前申请，因为排队时间长。

## 4. 工作方式（防止发散）

1. **每一步都要对应 H0–H3 中的一个。** 对应不上的不做，写进第 5 节的“暂缓清单”，由用户决定是否提升。不再新开 A、M、P、杠杆一类的编号。
2. **先写预期，再跑。** 每个分析和运行在提交之前，在对应文档里写下：要回答的问题、预期结果、怎样算通过。结果出来以后不改标准。
3. **深入，不追求广度。** 一个现象要追到机制，并且写成可以迁移的规律，比如“谁的差距大，为什么，随轮次怎么变，在什么条件下成立”，而不是只报一个数字。每个结果按四段写：
   - 现象；
   - 机制；
   - 规律；
   - 对假设的含义。
4. **少而精的检验。**
   - 同一个假设同时最多 2 个分析作业在跑；
   - 写新脚本之前，先确认现有脚本和数据能不能回答；
   - 一个结论不清楚时，先深挖已有数据，不要换一个新角度再开一个检验。
5. **方向变化要用户确认。** 结果推翻了某个假设时，写清楚并停下来问用户，不要自己换主线。
6. **资源规则不变：** 100 轮运行和数组作业要用户同意；12 轮以内要先告诉用户；其余见 `HANDOFF.md` 第 3 节。
